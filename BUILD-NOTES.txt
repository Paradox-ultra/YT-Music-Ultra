DL33 BUILD NOTES (Home and restyle, module-only)

SHIPPED DIFF
Unchanged rule: AndroidManifest version bump plus the module dex only. No base-APK resource, smali or
asset changes. No new permissions. No new network calls: Home reads only data the module already holds
(Library downloads, stored Library roster and playlist index, pins, cached artwork files on disk).

HOME TAB IN THE BOTTOM BAR: DEFERRED (needs a host change)
The Downloads destination is not added by this module. It is added by host bytecode already present in the
base APK: lac.ultraDownloadPivots(List) inserts the FEmusic_ultra_downloads pivot after Explore (called from
the host NavigationPatch), and lac.t(bbxl) routes that pivot to NativeIntegration.fromTab + Hooks.open,
redirects FEmusic_home to Search and calls NativeIntegration.leave for every other tab. The module only
receives those calls. Adding a Home pivot first in the bar "the same way" therefore means editing lac in the
base APK, which breaks the manifest+dex rule and audit.py's changed-file check. Runtime reflection into the
TabLayout was rejected as fragile. Decision (parent agent, DL33): module-only. Home opens from the Home pill at
the top of Downloads and is mounted in the same fragment_container, as a layer above Downloads. Bar order stays
Library, Search, Explore, Downloads; the default landing tab is unchanged.
To add the real tab later (host side): add a Home pivot (for example FEmusic_ultra_home, outlined house icon)
first in lac.ultraDownloadPivots, and a branch in lac.t that calls NativeIntegration.fromTab(this) and
NativeIntegration.openHome(); widen audit.py's changed-file set to match.

HOME BEHAVIOUR
- Back on Home closes Home and resumes Downloads underneath. Any host tab change (leave/closePanel) closes both.
- Home is not restored after an Activity recreation (rotation, process death); Downloads is, as before.
- Song tiles play through NativePlayback (native player and queue), queueing the other recent downloads.
- Playlist tiles: no in-module path that opens a native playlist page from module UI was found in this source
  (Downloads opens its own local view; Library pages are opened by the host). Home hands
  https://music.youtube.com/playlist?list=<id> to this app's own link handling (Intent.setPackage(own package),
  same link format the Library select mode already shares). If nothing in the app accepts it, the playlist's
  downloaded songs open in Downloads instead. NOT verified on a signed-in device: please check that tapping a
  playlist tile opens the native playlist page.
- Artist tiles open that artist's group in Downloads > Artists. Long-press is omitted.
- Pick up where you left off, fallback order: last played song (if downloaded), recent downloads (max 6), pinned
  playlists, then the remaining Library playlists; max 10 tiles, no duplicates.
- Your playlists: same names and order as Downloads > Playlists (native Library order, pins, Liked merged);
  device-only local playlists and Unmatched songs stay in Downloads.

DL50 (device report on DL50 host)
- Empty Ultra Home on every cold launch (regression in DL49), three parts: (1) HomeSource.playlists called
  LocalPlaylistCopies.entry per playlist (via PlaylistIndex.total and the Liked check), re-parsing and re-serialising
  the whole copies JSON each time: hundreds of full parses for a ~250-playlist Library, seconds on v7a. (2) DL49's 5 s
  fallback then rendered the empty-state page while data was still loading. (3) every repeated fromTab / self-check
  called refresh(), which discarded the load in flight, so the host enforcer's 8 ticks kept restarting it.
  Fix: one JSON read per load (copies + cached index, no seeding/writes); two-phase load (songs/last played/artists

DL51 (device report on DL51 host)

  fade-in (alpha 0 then animate) and are re-created on every render (two per load); on a busy cold start tiles could be
